# frogsdream content format

Every page on frogsdream.com is generated by `source/build.py` from one JSON file under `source/content/`.
This document is the contract for content writers. Check your files with:

```
python3 source/validate_content.py source/content/themes/bingo/christmas.json   # one or more files
python3 source/validate_content.py --all                                        # everything
```

The validator exits with code 1 on any error. Fix every ERROR before handing off; warnings are advice.
For themed pages it also compares your prose against every other themed page (5-word shingles, Jaccard
must stay under 0.25, and no shared sentence longer than 12 words).

## Golden rules (enforced)

* **No em dashes or en dashes** (U+2014, U+2013, also U+2012 and U+2015, and their HTML entities) anywhere,
  including titles, FAQ text, item lists and alt text. **No spaced hyphen used as a dash** (a hyphen with a space on each side).
  Do not swap them for colons either. Rewrite the sentence the way you would say it aloud.
  Hyphens inside words are fine: `90-ball`, `parents-to-be`, `free-to-print`.
* Write the brand as **frogsdream**: one word, always lowercase, even at the start of a sentence
  ("frogsdream is free to use", "Why frogsdream", "frogsdream's tools"). Never "Frog's Dream", "Frogsdream" or "Frogs Dream";
  the QA fails on them. Write it as plain text. The build draws it two-colored on the page by itself.
* US English, warm and plain. Address adults (teachers, parents, hosts), never children directly.
* No year numbers in titles or URLs. Say "every December", not a year.
* No trademarks or characters (Super Bowl, Disney, Pokemon, Wordle and so on). Use generic names.
* No invented statistics, reviews or personas. Cite a source with a link for factual claims.
* `title` is the full `<title>` text: **50 to 60 characters**. A trailing ` | frogsdream` is allowed if it fits.
* `metaDescription`: **140 to 160 characters**, unique on the site.
* Exactly one `h1` per page (the build adds it from your `h1` field; never put an `#` heading in prose).

## Where files go

| Page | File | URL |
|---|---|---|
| Home | `content/home.json` | `/` |
| Tool page | `content/tools/<tool-url-slug>.json`, e.g. `tools/word-scramble-maker.json` | `/word-scramble-maker/` |
| Themed page | `content/themes/<section>/<slug>.json` | `/<section>/<slug>/` |
| Section hub | `content/hubs/<section>.json` (`bingo`, `word-search`, `scavenger-hunt`, `word-scramble`) | `/bingo/` etc. |
| Cross-tool hub | `content/hubs/<slug>.json`, e.g. `hubs/christmas-printables.json` | `/christmas-printables/` |
| Guides hub | `content/hubs/guides.json` | `/guides/` |
| Guide | `content/guides/<slug>.json` | `/guides/<slug>/` |
| Static or legal page | `content/pages/<slug>.json` (`about`, `contact`, `privacy`, `terms`, `disclosure`, `premium`, `embed`) | `/<slug>/` |

Themed sections are `bingo`, `word-search`, `scavenger-hunt`, `word-scramble`, `bedtime-routine-chart`
(chart variants, URL `/bedtime-routine-chart/<slug>/`) and `reward-chart-maker` (URL `/reward-chart-maker/<slug>/`).

The list of allowed slugs, hub groupings, tools, the nav, the footer and the "In season now" entries
live in `content/site.json` (the catalog, owned by the foundation). A file whose slug is not in the
catalog is ignored with a warning. A catalog slot with no file yet is simply skipped, and links to it
are left out, so partial builds always work.

Embed pages (`/embed/bingo/`, `/embed/word-search/`, `/embed/word-scramble/`) are generated
automatically from the matching tool page file. You do not write them.

## Prose markup (used in every `body`, `intro`, FAQ `a` field)

A `body` is either one string or an array of strings. Each array element is one block, and a blank
line (`\n\n`) inside a string also starts a new block. Block types:

| You write | You get |
|---|---|
| Plain text (single line breaks are joined) | `<p>` paragraph |
| Lines all starting with `* ` (or `- `) | bulleted list |
| Lines all starting with `1. `, `2. ` ... | numbered list |
| `### Heading` | `<h3>` subheading (use for long sections, never `#` or `##`) |
| `> text` | green tip box (`<p class="note">`) |
| A block starting with `<` | raw HTML, passed through untouched. Allowed only in guides, hubs, home and static pages. |

Inline: `**bold**`, `*italic*`, `[link text](/bingo/christmas/)`.
Internal links must be site paths that exist in `site.json` and end with `/` (the validator checks).
External links must be `https://` and get `rel="noopener"` automatically.

JSON tip: write a list block as one string with `\n` between items:
`"* First idea\n* Second idea\n* Third idea"`.

## Themed page (bingo, word search, scavenger hunt, word scramble, chart variants)

Example: `content/themes/bingo/baby-shower.json` (copy its shape). Fields:

| Field | Required | Notes |
|---|---|---|
| `shortTitle` | yes | Name used in links, cards and breadcrumbs, e.g. `"Baby Shower Bingo"`. |
| `title` | yes | `<title>`, 50 to 60 chars. Vary the pattern; see SPEC section 4. |
| `metaDescription` | yes | 140 to 160 chars. |
| `h1` | yes | e.g. `"Baby Shower Bingo Cards (Free Printable Generator)"`. |
| `intro` | yes | 1 to 2 answer-first sentences shown under the H1 (inline markup only). Counts as prose. |
| `toolTitle` | no | Title pre-filled in the generator and printed on the sheets. Defaults to `shortTitle`. |
| `items` | yes | The curated list (see "Items" below). It pre-fills the tool and is printed visibly as the list section. |
| `itemsNote` | no | One or two sentences under the list heading. Theme-specific, please. |
| `defaultOptions` | yes | Object that pre-configures the tool (option names per tool in TOOL-CONTRACT.md). `{}` is allowed. |
| `season` | yes | Month numbers when the theme is in season, e.g. `[11, 12]`; `[]` for evergreen. |
| `hubs` | yes | 1 or 2 cross-tool hub slugs from `site.json` `crossHubs` (chart variants may use `[]`). |
| `related` | yes | Exactly 6 other themed pages as `"section/slug"`, e.g. `"word-search/christmas"`. |
| `relatedHeading` | yes | e.g. `"More Christmas printables"`. |
| `sections` | yes | Ordered prose sections, each `{ "role", "heading", "body" }`. |
| `faq` | yes | 2 to 4 `{ "q", "a" }`. Questions end with `?`. Unique to the theme. |
| `noAds` | no | `true` removes manual ad slots and AdSense from the page. |

**Section roles.** Required: `howTo`, `variations` (3 or more list items or `###` subheadings), `tips`,
`printing`. Optional: `safety` (required in practice for outdoor hunts: adult supervision, stay in sight,
no picking protected plants), `about`, `extra`. A section with role `list` overrides the heading and
note of the visible list section instead of adding prose. The build places an ad slot after `howTo`
and another before the FAQ.

**Word counts** (intro + all section bodies + FAQ questions and answers):
350 to 700 words; 600 to 900 for the high-value bingo themes (baby-shower, bridal-shower, christmas,
halloween, thanksgiving, road-trip, esl-\*, sight-words-\*).

**Page order as rendered:** breadcrumb, H1, intro, the generator (pre-filled), Mega Pack line (hidden
until the owner sets PACK_URL), list heading + note + visible list, sections in your order (ad slot after
`howTo`), ad slot, FAQ, related links (your 6 + your cross hubs + the section hub + the main tool).

### Items

| Section | Count | Format |
|---|---|---|
| bingo | 24 to 75 | Strings. Addition-facts style themes use objects `{"square": "12", "call": "7 + 5"}`. Number pages (`75-ball-bingo-cards` etc.) may leave `items` empty when `defaultOptions.mode` is `"75"`, `"90"` or `"30"`. |
| word-search | 12 to 25 | Strings, 3 to 15 letters after removing spaces and punctuation (12 or fewer suits the kids' default grid). |
| scavenger-hunt | 20 to 40 | Strings. Optional points after a bar: `"Animal tracks \| 3"`. |
| word-scramble | 12 to 30 | Strings with 3 or more letters and at least 2 different letters. Short phrases are fine. |
| bedtime-routine-chart / reward-chart-maker | 3 to 14 / 2 to 14 | Strings (step or task labels). Optional icon and time after bars, e.g. `"Brush teeth | brush-teeth | 7:30 PM"`; see TOOL-CONTRACT.md. |

Items appear in the tool textarea one per line: strings as written, `{square, call}` as `square | call`,
`{text, points}` as `text | points`.

## Tool page (`content/tools/<url-slug>.json`)

Fields: `shortTitle`, `title`, `metaDescription`, `h1`, `intro`, `items` (the sample list the tool
starts with), `defaultOptions`, `toolTitle`, `sections` (any headings, roles optional), `faq` (optional,
2 to 8), `featured` (optional: up to 12 `"section/slug"` refs shown as "Ready-made themes"; default is
the first 12 built themes of the tool's section), `featuredHeading` (optional), `shell` (optional: `"custom"` for the bingo caller, which draws its own UI; see TOOL-CONTRACT.md).
Recommended prose: 300 to 1,200 words (warning only).
The build adds WebApplication, BreadcrumbList and FAQPage JSON-LD, the featured themes and a link to the hub.

## Hub page (`content/hubs/<slug>.json`)

Fields: `shortTitle` (link text), `title`, `metaDescription`, `h1`, `intro` (shown as the lede),
`sections` (prose below the links), `faq` (optional), `linksHeading` (optional), `ogTitle` (optional, text
on the generated OG image), `extraLinks` (optional list of `{ "heading", "paths": ["guides/..." or "/path/"] }`).

* Section hubs list every built theme of that section, grouped as in `site.json`.
* Cross-tool hubs list every built themed page whose `hubs` contains this hub, grouped by tool, plus `extraLinks`.
* Every hub also shows the "In season now" block.
* Word counts: cross-tool hubs 300 to 500 words (intro + sections + FAQ); section hubs 120 to 700 (warning).
* JSON-LD: CollectionPage with an ItemList of the linked pages, plus BreadcrumbList.

## Guide (`content/guides/<slug>.json`)

Fields: `shortTitle`, `title`, `metaDescription`, `h1`, `intro`, `sections` (raw HTML blocks allowed for
diagrams and inline SVG), `faq` (optional), `sources` (list of `{ "label", "url" }`, https only, rendered as
a Sources list), `related` (refs like `"bingo/christmas"` or `"/bingo-card-generator/"`), `relatedHeading`,
`scripts` (optional, e.g. `["guide-patterns.js"]`, loaded from `/assets/js/`), `cardBlurb` (optional text on
the guides hub card), `datePublished` (optional, defaults to the build date), `adSlotAfter` (optional section index the
first ad slot follows, default 1; keep it away from interactive widgets).
Word count: 1,000 to 1,800. JSON-LD: Article (author and publisher are the frogsdream organization).

## Static and legal pages (`content/pages/<slug>.json`)

Fields: `shortTitle` (or `navLabel`), `title`, `metaDescription`, `h1`, `intro` (markup, raw HTML allowed),
`sections`, `faq` (optional), `noindex` (optional), `noAds` (optional; /privacy/, /terms/, /contact/,
/premium/ and /embed/ never load ads anyway), `mascot` (optional pose shown beside the H1: `mascot`,
`waving`, `sleeping`, `pencil`, `celebrating`), `scripts` (optional), `path` (optional URL override).
`premium.json` adds `"product": { "name", "description", "price": "7.00", "images": ["/assets/img/..."] }`
for Product JSON-LD.

**Hooks you can use in raw HTML** (handled by `site.js`, driven by `config.js`):

* `<a class="btn btn-primary" data-pack-buy data-label="Get the Mega Pack for $7">Coming soon</a>`
  becomes a checkout link when `PACK_URL` is set, otherwise stays "Coming soon".
* `<span data-pack-price>$7</span>` shows `PACK_PRICE`.
* Any element with `data-pack hidden` is shown only when `PACK_URL` is set.
* `<span data-email></span><noscript>hello at frogsdream dot com</noscript>` becomes a mailto link built from `CONTACT_EMAIL`.
* `<a href="/privacy/#choices" data-privacy-choices>Privacy choices</a>` reopens Google's consent message when available.
* `{{BUILD_DATE}}` anywhere in a page is replaced with the build date, e.g. "October 4, 2026" (used for policy dates).
* `<!-- OWNER: replace -->` comments are kept as written (use one next to `[OWNER FULL NAME]` on the privacy page).

## Home (`content/home.json`)

| Field | Notes |
|---|---|
| `title`, `metaDescription` | As usual. |
| `h1`, `subhead` | Per the spec. Subhead is inline markup. |
| `intro` | Optional short markup under the subhead. |
| `cta` | Optional `{ "label": "Make bingo cards", "path": "/bingo-card-generator/" }` for the hero button. |
| `tools` | 7 cards: `[{ "tool": "bingo", "blurb": "..." }]` using tool ids from `site.json` (bingo, wordsearch, scavenger, scramble, routine, reward, caller). Name, link and mascot come from the catalog. |
| `toolsHeading`, `popularHeading`, `hubsHeading` | Optional headings. |
| `popular` | Exactly 12 `{ "path": "bingo/baby-shower", "label": "Baby shower bingo" }`. |
| `why` | `{ "heading": "Why frogsdream", "body": markup }` (truthful claims only). |
| `sections` | Optional extra prose at the end. |

Home prose (intro + subhead + why + sections + card blurbs) must total 300 to 500 words.
The build adds the tool cards, In season now, popular themes, hub cards, and WebSite + Organization JSON-LD.

## What the build adds for you

Canonical, Open Graph and Twitter tags, OG images (per tool, per hub, one default), breadcrumbs and
BreadcrumbList, WebApplication / FAQPage / CollectionPage / Article / WebSite / Organization / Product
JSON-LD (FAQ JSON-LD text is the plain text of your visible FAQ, so they always match), the In season now
block, related links, sitemap.xml, themes.json, and QA (unique titles and descriptions, one H1, page size
under 60 KB, banned dashes in all output, JSON-LD lint, broken links, 3 or more inbound links per page).
