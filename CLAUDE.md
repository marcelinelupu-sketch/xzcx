# frogsdream.com: project guide for Claude Code

Read this first. It explains what the site is, how it was built, how to change it safely, and what is still left to do.

## 1. What this is

**frogsdream.com** is a free printables website for teachers, parents and party hosts, owned and run by **Wojciech (Wojtek) Niedźwiecki**, a private individual in Poland (unregistered small activity, "działalność nierejestrowana"). Wojtek is not a programmer. He uploads files to Hostinger through the hPanel File Manager. Explain things to him in plain, clear English (it is his second language) and give exact click paths.

What the site offers:

* **7 free browser tools:** bingo card generator (word bingo, 75-ball, UK 90-ball, numbers 1 to 30), word search maker, scavenger hunt generator, word scramble maker, bedtime routine chart, reward chart maker, and an online bingo caller (projector mode, voice).
* **About 120 themed pages** (baby shower bingo, Christmas word search, ESL animals bingo, nature walk scavenger hunt and so on), each with its own curated word list and unique prose. Plus 8 cross-tool hubs, per-tool hubs and 8 guides. About 166 pages in total.
* **The frogsdream Mega Pack:** a paid $7 download (247 PDFs, 2,793 pages) of ready-made printables for every theme.

How it makes money:

1. **Google AdSense** (not switched on yet; see section 7).
2. **Mega Pack sales** through Stripe.

Why this concept: a research phase (10 agents plus 3 judges) picked it because "printable" searches are transactional, and Google's AI Overviews rarely answer them, so clicks still reach sites. The model is proven (Bingo Card Creator, myfreebingocards.com), seasonal traffic comes back every year, and the site runs hands free. Realistic expectations given to the owner: about $0 for the first months, about $20 to 100 a month by month 12, with seasonal peaks around Christmas. Be honest with him about numbers; never hype.

## 2. Hard rules (read before writing anything)

1. **No em dashes or en dashes** (U+2014, U+2013) anywhere in human-readable text: site content, titles, meta, JSON-LD, PDFs, docs, READMEs, commit messages. Also no spaced hyphen used as a dash (" - "). Do NOT replace them with colons either. Write sentences the way they would sound spoken aloud. The QA fails on any dash.
2. **The brand is "frogsdream"**: one word, always lowercase, even at the start of a sentence. Never "Frog's Dream", "Frogsdream" or "FrogsDream". `build.py` automatically colors it in page text ("frogs" green #2F8F5B or #287D50, "dream" purple #3B3A6B), so content files just write `frogsdream`. The QA fails on old brand variants.
3. **Never touch `/lessoncorner/`** on the server. It holds materials for an English school Wojtek works for. The `.htaccess` (generated by `build.py`) deliberately leaves that folder alone: index.php allowed, no index.html rewrite, no long caching, noindex. Keep those rules. frogsdream must never compete with Lesson Corner's lesson business (it sells no lessons or tutoring).
4. **No third-party requests while ads are off.** Everything (jsPDF, the Fredoka font) is self-hosted. No Google Fonts, no CDNs, no analytics. The QA fails on any other host.
5. **No cookies or localStorage of our own.** The tools keep user input in `sessionStorage` only. This keeps the site free of a cookie banner under EU rules. The QA checks it.
6. **Honesty:** no fake reviews, user counts, testimonials or personas. The About page says content was written with AI assistance and reviewed for accuracy.
7. **No trademarks** in themes or word lists (Lego, Popsicle, Band-Aid, Disney and so on). Use generic words.
8. **Never put a zip inside the build output.** The Mega Pack is uploaded to the server by hand (see section 5). The QA enforces this.
9. Do not edit `public_html/` by hand. Edit `source/` and rebuild.

## 3. How it is built

Plain static HTML, CSS and vanilla JavaScript, generated by a Python script. No framework, no server code, no database.

| Path | What it is |
|---|---|
| `source/build.py` | The static site generator. Reads content JSON, CSS partials and static files, writes `public_html/`. Also generates sitemap.xml, robots.txt, .htaccess, ads.txt, the IndexNow key file, OG images (Pillow), JSON-LD, hubs, related links, and the "In season now" block. |
| `source/fdlib.py` | Shared helpers for the build and the validator. |
| `source/validate_content.py` | Content rules: word counts, title and meta lengths, banned characters, list sizes, similarity between pages. |
| `source/content/site.json` | The catalog (all slugs, hubs, nav, footer) plus `operator` (name, address), `packAvailable`, and `legal.updated` (policy date). |
| `source/content/` | All page content as JSON: `themes/<tool>/<slug>.json`, `hubs/`, `guides/`, `tools/`, `pages/`, `home.json`. Format in `source/CONTENT-FORMAT.md`. |
| `source/css/` | CSS partials, joined in name order and minified into `assets/css/site.css`. **Budget: under 25 KB minified, and it is about 24.8 KB now.** Trim before adding. |
| `source/static/` | Copied verbatim to the site root: `assets/js/*.js` (tools, toolkit, site, pdf, rng, print), `assets/js/vendor/jspdf.umd.min.js`, images, fonts, favicon, and the hidden download page. |
| `source/static/assets/js/config.js` | Runtime settings: `ADSENSE_CLIENT`, `PACK_URL`, `PACK_PRICE`, `TIP_URL`, `CONTACT_EMAIL`. |
| `source/tools/` | Each tool's option controls. The JS plugin contract is in `source/TOOL-CONTRACT.md`. |
| `source/art/` | Scripts that draw the frog mascot (5 poses), icons and sample images. |
| `source/megapack/build_megapack.py` | Builds the Mega Pack PDFs (reportlab, vector, fonts embedded) and its zip. Deterministic. |
| `source/tests/`, `source/qa/` | Unit tests, browser tests (Playwright), static checks, Lighthouse. Runner: `source/qa/run_all.sh`. |
| `source/SPEC.md` | The original full spec. Its OWNER OVERRIDES section at the top always wins. |
| `deliverables/` | What the owner downloads: the upload zip, the Mega Pack, `OWNER-README.html` (his setup checklist) and `COMPLIANCE-REPORT.md`. |

Requirements: Python 3.11 with Pillow, reportlab and svglib; Node 22 with Playwright and Chromium; poppler-utils.

### Commands

```bash
# Quick check of one content file
python3 source/validate_content.py source/content/themes/bingo/baby-shower.json

# Build only
python3 source/build.py --strict --force

# Quick QA (use for looks-only changes: CSS, layout, text). Takes a few minutes.
QUICK=1 bash source/qa/run_all.sh

# Full QA (use when tool JS, PDFs or word lists change)
bash source/qa/run_all.sh

# Rebuild the Mega Pack (only when pack content changes)
python3 source/megapack/build_megapack.py
```

A passing `run_all.sh` regenerates `deliverables/frogsdream-public_html.zip`. Use the quick QA for cosmetic changes; the owner asked to keep token use and time down.

## 4. Hosting and deployment

* Hostinger shared hosting. The site lives in `public_html/`, next to the owner's `lessoncorner/` folder.
* **To deploy:** the owner uploads `deliverables/frogsdream-public_html.zip` to the main files area (`/files/`) in File Manager, chooses Extract, types the folder name `public_html`, does NOT select a folder in the list, ticks **"Overwrite existing files"**, then deletes the zip. That merges the new files into the existing public_html.
* Tell him to back up public_html first (select all, Compress, Download).
* Everything he needs is built into the zip (name, address, Stripe link), so nothing is lost when he re-uploads. The only value he will ever paste by hand is `ADSENSE_CLIENT` in `config.js`, and re-uploading a zip overwrites it unless you also put it in `source/static/assets/js/config.js`. Once AdSense is approved, put the ID into the source too.

* After payment Stripe **redirects** to the hidden page `https://frogsdream.com/pack-download-b0b5f94d131b/` (source: `source/static/pack-download-b0b5f94d131b/index.html`, noindex by meta tag and by `.htaccess` header, no ads).

A faulty file gets a working copy, or a refund if it can't be fixed. Keep this wording identical everywhere: premium page, terms, download page, Start Here PDF.
* There is no automatic email with the download link. Buyers get the download page instantly plus Stripe's receipt. If someone loses the link, the owner replies by hand with the download page URL. Only build an email system (Stripe webhook plus PHP on Hostinger) if lost-download emails become a real problem.
* If the download link ever leaks widely (downloads far above sales), rename the hidden folder and update the redirect in Stripe.
